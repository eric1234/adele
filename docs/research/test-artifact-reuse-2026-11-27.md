# Can independent test suites reuse compiled bytes?

**Subsequent decision:** The pilot recommendation below is historical. The [follow-up measurements and retirement decision](verified-aot-observations-2026-11-28.md) explain why the maintained targets compile fresh.

Role: Non-normative CI research, 2026-11-27. Source: [`32fb206478283b87fa10de046223fc945461c839`](https://github.com/eric1234/adele/commit/32fb206478283b87fa10de046223fc945461c839), fetched `origin/main` including [#283](https://github.com/eric1234/adele/pull/283). Follow-up to the [CI baseline](ci-performance-2026-11-26.md#2-eliminate-duplicate-desktop-setup-reuse-bytes-not-live-fixtures), not a cache specification. No pilot code, CI policy or fixture changes are part of this report.

**Recommendation: implement lazy, worker-private reuse for just the shared host and stock Git AOT in the four Linux Git-hosted suite setups, gated on a complete input and publication fence.** In four local runs all 73 cases passed; two fresh controls compiled 12 AOTs each and two scoped workers compiled 7 each. On the closest warm pair the worker fell from **227 to 213 s**. The avoided compiles themselves cost **16-19 s** per control; validating the scope was not free. Expect to save roughly **13-16 s of preparation** on this machine, not 44 s on every hosted job. Expand to desktop/interaction host callers only after testing the identity boundary. Keep shards unchanged.

## Local experiment

Linux `6.8.0-149-generic`, x86-64 i5-1135G7 (4 cores/8 threads), 39 GiB, local SSD. Explicit `FLUTTER_ROOT` and SDK `bin` first on `PATH`; verified Flutter **3.38.10** `c6f67dede3d4aa1aa7a69dd56a3494a5cde6cc80`, engine `cafcda5721a78a7884db92f13c5e89f7643d52dd`, bundled Dart **3.10.9**, Rust **1.93.0**, unchanged tracked lockfile. An initial shim-selected resolution with the wrong SDK was discarded, not included in either arm. Check `.dart_tool/package_config.json`'s `flutterRoot` and `generatorVersion` as well as `flutter --version --machine`. Same checkout, user SDK/pub cache, no cache purge or parallel test targets; not a dedicated hosted runner.

1. From the root run `dart tools/adele.dart bootstrap` (55.63 s here). From `plugins/git/packages/desktop_tests` run `flutter test --no-pub --concurrency 1 --reporter expanded test/git_task_anchor_store_test.dart` (128.57 s, 26 passes; included initial Flutter/native hook compilation). Do **not** subtract this from subsequent runs or charge it to AOT. No CodeForge build/loader is required. Leave Flutter/kernel/native/pub state in place for both arms.
2. In a disposable checkout put a wall timer around each of the four complete `setUpAll`s and temporarily dispatch each existing `compileAotSnapshot` process via a logging wrapper in its unchanged cwd. Record entrypoint, output, child wall, size and SHA-256; propagate failures. Control A forwards the original argv on every request. For B only, a parent passes a new private temp directory's absolute path in the child environment and removes it on exit. This models a single-target launcher's scope without making a production builder depend on test configuration.
3. B intercepts **only the two literal stock root-relative recipes**. Under a per-entrypoint inter-process lock (`flock` in the short-lived Python 3 helper), read root package config and graph; follow normal dependencies from the entrypoint owner (12 packages each). Enumerate all `lib/**/*.dart`, owning `bin/**/*.dart`, manifests, root lock/config/graph, contract inventory, helper and compiler implementation; reject package hooks in those closures. Hash sorted paths, resolved paths, bytes, Linux dev/inode/size/ctime-ns/mode, cwd, native target and fixed options, including SDK driver, runtime, `dartvm`, dartdev/gen-kernel snapshots, `gen_snapshot`, platform dills and SDK metadata. On miss, compile privately with `--depfile DEP --packages ABS_ROOT_CONFIG`, fixed producer basename `snapshot`; require the intended entrypoint and all depfile paths in the preobserved set. Repeat discovery/hash before atomic directory rename. Check size/digest, copy to the suite's **original path**, verify copied digest and repeat discovery/hash before return. Leave the other five AOTs and both frontend compilers alone. A hit is not a no-op.
4. From the root, use `/usr/bin/time -f 'wall=%e user=%U sys=%S maxrss=%M' dart tools/adele.dart test --target git_desktop_tests --ci` for **A, B, B, A**, serially with a new scope every B. Compare launcher `START`-`PASS`, whole command, compiler calls and setup timers, not just a fast second `flutter test`. No edits to the cases, deadlines, isolation, asserts, preparatory generator or launcher selection. Python instrumentation and one final output digest per request are common to both arms; compiler wall is the real subprocess only. The exact numbers below are not hosted predictions.

**Equivalent for these tests is not identical production bytes under every filename.** All eight control host builds (same basename) had the same SHA-256. Git `git.aot`, `stock.aot` and `backend.aot` had three different digests, stable across controls. In the independent checks, comparing SHA-256 of each named ELF section (`readelf -SW` offsets/lengths) found **only `.debug_info` changed** for each of the four inputs. A third host/Git build retaining the diagnostic options but restoring `host.aot` reproduced the first **whole-file** digests (2.73/4.66 s). The [pinned snapshot writer](https://github.com/dart-lang/sdk/blob/3.10.9/runtime/bin/gen_snapshot.cc) passes the output basename as the compilation-unit identifier. Use a stable producer basename and a verified verbatim copy; never strip or rewrite an ELF to force equality. Actual execution passed with the fixed basename in both B workers. An assertion about original debug names, symbolization, compiler diagnostics or truly fresh output is **not eligible**.

**Fault probes.** In a disposable root, copy the real host package, point a copy of the resolved config at it, keep the other resolved dependencies real, and use a fresh scope. Issue two simultaneous helper subprocess requests for the same key: exactly one compile/one hit, two distinct destination inodes with equal digests. Overwriting a delivered copy did not affect the next hit. Flip one retained byte without changing length, remove the file, or truncate it: each was a miss with a real rebuild. Editing transitive `lib/src/backend_host.dart` forced a miss. Invalid Dart gave a real compiler failure, no published stage or fallback, and retry succeeded after restoring source. A second edit after observing a miss's private stage (after pre-fingerprint) was rejected by the post-compile fence. These were host probes, not 73 extra failure tests.

The pilot is **not a complete cache protocol**: no hostile-receipt or symlink confinement proof, authenticated launcher handoff, atomic destination delivery, generation-input/negative-directory fence, SIGKILL recovery test, or multi-isolate Dart lock test. It ran a fixed Linux toolchain/environment without concurrent pub resolution. Production-grade checks may cost more. In particular, do not ship the Python shim or put opt-in caching into the generic plugin builder. The following are implementation gates, not properties inferred from green tests.

## Identity and lifetime

**Do not start the production desktop build to get two files.** [`backend_artifacts.dart`](../../tools/backend_artifacts.dart) prepares tools, generates contracts, builds a 26-stage graph, hashes SDK/Flutter and stage inputs, stages components, checks tools before use, rediscovers/re-hashes before publication and validates native identities where applicable. [`desktop_build_inputs.dart`](../../tools/desktop_build_inputs.dart) is an SDK-only subprocess coordinator and checks the response; [its worker](../../tools/desktop_build_inputs_worker.dart) discovers every backend and frontend, following resolved imports/exports/parts and conditional alternatives and including owner metadata/assets. Filtering the returned JSON still pays for all stages. In the baseline, source-worker startup plus discovery was 10.4 s; even compiling the discovery worker alone cost 7.6 s in a small fixture. Neither is an incremental cost measured for this pilot.

**Reuse the checks, not the persistent namespace.** The closer precedent is [`desktop_tool_artifacts.dart`](../../tools/desktop_tool_artifacts.dart): start with a conservative, resolved package-library/owned-source superset, stat/hash around inventory, compile against the exact config with `--depfile`, reject an unexpected target or uncovered input (`validateToolDepfile`). A backend-only selector must narrow discovery *before* traversal. [`desktop_artifact_cache.dart`](../../tools/desktop_artifact_cache.dart) has useful batch hashing, stat fences, private stages, nonempty non-link file inventories and rename publication. Its checkout-wide lock/buckets/installation snapshot are not a test scope. `compileAotSnapshot` alone only checks success and existence; it is not an integrity validator.

The implementation would need the following evidence for every reusable generation:

1. Own the recipe: allow only canonical stock entrypoints in this checkout, root cwd/config, pinned executable, target OS/ABI, fixed flags, helper implementation and a defined compiler environment. Do not accept arbitrary entrypoints with claimed stock IDs, different working directories, debug/experiment/define/cross-target flags, or an opaque caller-supplied key. Diagnose/refuse unexpected config shadowing, hooks or implicit resolution; do not silently change a caller's compilation semantics.
2. Bind actual resolved package config **and graph**, language versions, manifests/overrides/lock, participating source bytes (including external pub libraries), relative/canonical paths and directory/link/absence probes that affect resolution. Check compiler-observed dependencies on a miss, not *only* a post-compile depfile: a source can change the closure while the compiler runs. The pinned [CLI](https://github.com/dart-lang/sdk/blob/3.10.9/pkg/dartdev/lib/src/commands/compile.dart) also checks native assets via its cwd; an explicit `--packages` does not make arbitrary hooks irrelevant. The [AOT pipeline](https://github.com/dart-lang/sdk/blob/3.10.9/pkg/dart2native/lib/dart2native.dart) uses the bundled driver, runtime, dartdev and gen-kernel snapshots, platform dill and `gen_snapshot`. Validate paths and bytes, not just `dart --version`. Do not broaden this recipe to PTY/native hooks without their own inputs and toolchain.
3. Keep maintained generation *before* workers and the independent, read-only `generate --check`. The compiled closure includes generated siblings (e.g. Git's Diff Viewer review contract). A checksum of yesterday's `.g.dart` cannot prove today's declarations, generator and resolution produced it. Preserve [the generator's authority](../../packages/contract_codegen/README.md#incremental-linux-preparation); fence generation inputs/outputs through admission and reuse, abort/restart maintained preparation if their provenance changes. Do not turn production receipts into permission to skip test generation. Dirty but stable sources are valid; a clean Git SHA is neither necessary nor sufficient.
4. Compare both **membership and bytes**, plus Linux identity/change metadata around discovery, compilation, publication and copy. Include directory/negative probes for additions, replacements, symlink swaps and edit/restore. Refuse a hybrid graph, drain/clean staging, allow retry from a new stable observation; never substitute a previous generation on compiler failure. A stat-only fast path, mtime/size, or a digest recomputed for the first time *after* compilation is not a mutation fence. Like a fresh compile this is a point-in-time preparation guarantee, not a lock against arbitrary future edits. Where a mutable input cannot be fenced, compile from a verified private input snapshot or leave it ineligible.
5. Publish only successful, privately staged, exact, regular, nonempty AOT output with size, SHA-256 and expected mode. Record the producer's digest independently of the destination. Serialize per identity; recheck after acquiring the lock. Atomically rename a complete generation on the same filesystem. Reject missing, malformed, swapped, linked, empty, unexpected or digest-mismatched entries. Copy (not hardlink) into a private staging file at the consumer and verify before handing it over. Never let a failed validation leave an admissible destination. Do not expose the retained path as the installation. A receipt and payload writable by the same caller are not an authentication boundary.

**Scope ownership.** In [`_runTests`](../../tools/adele.dart) the boundary is the `execute(target)` callback, after selection, source preparation and generation. Create a random mode-0700 temporary scope **per participating child**, set an absolute locator only in that child's `Process.start` environment, merge rather than replace the CodeForge loader and preserve normal environment/credential policy. Do not change parent-global environment or discover a scope by searching upward. A direct `flutter test` without that handoff compiles normally. Clear stale/inherited locators when launching unrelated workers and avoid forwarding scope authority to backend runtime processes. Distinct target roots and checkout identities prevent collisions between invocations. [`runTestTargets`](../../tools/test_runner.dart) serializes Flutter targets with a shared normalized cwd *within* a launcher; it neither shares Dart statics across suite isolates nor locks other launcher processes. Different cwd targets can overlap; non-CI Flutter may execute multiple files at once.

Eager launcher preparation of the two files would avoid racing producers and is reasonable for a known complete Git selection, but would delay worker admission, need its own consumption fence and do unused work on filters/source-only runs. Prefer lazy requests; don't add a second suite-to-prerequisite registry. A per-process `Map<key,Future>` alone does not reach another suite. Use one worker-owned coordinator that serializes requests, or one short-lived helper process per request with a real inter-process lock and an in-process gate where necessary. Dart POSIX file locks alone do not exclude two isolates of the same process. Do not add a persistent server. Await child exit and admitted requests before recursive cleanup in `finally`; handle cancellation/termination by stopping admission and draining or terminating the child tree. On hard kill, no `finally` is guaranteed: an orphan in OS temp must never be rediscovered/reused; use runner/temp lifetime or a bounded, ownership-safe stale-temp policy, not deletion of another active job's scope.

Consumers keep their existing runtime, registry, provider generations, repository/worktrees, mutable installations, Project backing, credential/network isolation, per-case teardown and corruption/replacement/retirement checks. Only immutable *bytes* can cross suites. Fresh compiler, compiler failure and deliberately broken/missing installation tests remain independent. No shared live host, `.adele`, `.dart_tool`, job artifact, upstream producer gate or cross-invocation cache.

## Other opportunities and CI allocation

* **Terminal first if the budget is one suite change.** Normal ChatGPT's T3b and T2 each call `installTerminal`: stock Terminal EVC plus [`prepareGitPtyHelper`](../../tools/git_pty_artifact.dart) (`cc -std=c11 -O2 -Wall -Wextra -Werror <git>/native/git_pty_helper.c -o OUT -lutil` in the root). Lazily prepare one pair per suite and copy into each case's Terminal/Git installations. This saves one of each, not every Terminal build. Different C children and fault-injected PTY binaries are ineligible. Smaller risk and reach than AOT; no measured comparative wall benefit here.
* **Defer general EVC reuse.** Stock compilation consumes hand-assembled source maps, generated eval clients, UI stubs, bridge/plugin declarations and frontend harness configuration. For example, the [Diff compiler](../../app/tool/diff_viewer_frontend_compiler.dart) generates clients from contract sources; the [Source compiler](../../app/tool/source_editor_frontend_compiler.dart) reads a library tree and bridge sources. The pinned evaluator retains type references keyed by library ID across `Compiler` instances; see [`PreparedPortableGit`'s isolated stock compiler](../../app/test/support/prepared_portable_git.dart). Preserve independent `Isolate.run`, real assembly, failure/corruption and mount/retirement tests. Neither a fresh `Compiler()` in a shared isolate nor a frontend name is a key. AOT identity does not cover EVC.
* **CodeForge:** I1's Open in Source needs the native editor; no I2 case does on this assignment. Both build because `nativeCodeEditor` is target-level. A separate selection-derived prerequisite could avoid one independent native preparation; don't hard-code shard 2 or remove native TOML/credential hooks or source verification. Measure an ordinary cold runner's build and admission before ranking it over AOT.
* **Launcher/generation:** CI now uses `resolve-workspace` before `test`/`analyze`, not two full semantic generations. Keep discovery, both editor source leases, authoritative contract verification and failure-before-worker behavior. Full generation, Flutter startup and native hooks still cost time; none is a host AOT hit. Investigate those separately, not via a generated-byte handoff.

## Implementation and acceptance gates

1. **Establish eligibility first.** Add a development-only typed host/Git recipe and a narrow input capture in tools/test support, modeled on `DesktopToolArtifacts`. No changes to production cache admission. Prove package resolution equivalence to a real fresh compile on this pin; require depfile target, entrypoint, package config and complete coverage. Refuse unsupported cwd, flags, hooks, symlinks/ambiguous roots or unverifiable generation. Match dirty source, generated part, dependency in pub cache, changed package location, SDK/compiler/runtime, architecture, options and helper changes independently. Test new imports, optional overrides, missing/generated/edited-restored inputs and directory membership changes during fingerprint, compile and copy. Do not ship reuse if this fence cannot be established economically.
2. **One worker, two lazy products.** At the launcher child boundary create a private scope for `git_desktop_tests` only. Route only the four named suite setups' eligible calls to the test helper; direct `flutter test`, ineligible fixtures and fresh compiler/failure tests still call `compileAotSnapshot`. Use private temp+rename publication and verified, independently mutable copies. Test one/no request, two independent suites, two workers in one launcher and independent launchers, simultaneous same-key requests across processes and isolates, cancellation/process death, lock release, cleanup and retry. Inject nonzero exit, absent/empty output, bad receipt, swapped/same-size/linked payload and damage between read and copy. No old artifact fallback and no path into a later invocation.
3. **Integrate and measure before widening.** Use real AOT host/backend startup and the complete six-file/73-case Git selection with no coverage, skip, timing or credential changes. Keep direct no-scope fresh startup and genuine compile-failure coverage; compare cold-miss, subsequent hit and damaged-output repair against private-copy mutation. Re-run a warm counterbalanced comparison reporting actual call counts, full setup, CPU and worker totals; compare subsequent **ordinary** CI observations including admission and runner-minutes. Require seven not twelve AOT calls in the scoped Git worker, no shared mutable state, and a net preparation win including the complete fence. Patterns to port, not weaken: `test/tools/{desktop_build_inputs,desktop_tool_artifacts,desktop_source_invalidation,desktop_identity_invalidation,desktop_final_input_fence,desktop_publication_recovery}_test.dart`, plugin-builder argv/failure tests and contract-codegen's independent fresh `--check` vs incremental output proof.
4. **Then consider app adopters, not new shards.** Start with D4 host, then shared-helper sites on remaining shards; handle raw absolute-path/parallel callers separately. Qualify OpenAI/Local Directory only where their per-worker multiplicity and measured net cost justify another recipe. A 52-call ceiling across seven workers is useful for runner consumption; it cannot remove 52 calls from any one critical path. Keep EVC, PTY, CodeForge metadata and cross-job artifact distribution outside this change. Reassess allocation only after the preparation change has ordinary CI coverage.
